# Architecture Decision Records

Record decisions that meaningfully affect architecture, data integrity, security, or long-term maintenance. Keep each decision concise and include context, the chosen approach, alternatives, and consequences.

Use filenames such as `0001-offline-first-local-database.md`. Number records sequentially. Proposed decisions to document as implementation choices are:

1. Offline-first persistence and repository boundaries.
2. Currency representation and rounding rules.
3. Shop scoping and data ownership.
4. Inventory movement ledger and transaction consistency.
5. AI provider boundary and read-only initial permissions.

These are project principles in the current plan; finalize each record when implementation details are selected.
